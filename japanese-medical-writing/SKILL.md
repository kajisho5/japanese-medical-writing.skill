# 日本語医学論文スキル

和文の医学論文を「投稿してそのまま査読に出せる」水準まで仕上げるための手順。
最優先は**事実の忠実性**。文章のうまさより、書いてある数値・引用・手続きがすべて本物であることのほうが重要。医学論文で捏造された数値や存在しない文献が一つでも混ざると、著者の研究者生命と患者の安全の両方を損なうため。

## 動作の基本：完全ローカル

医学論文の原稿は、患者情報・未発表データ・査読コメントという外に出してはいけない情報の塊なので、このスキルは**ネットワークを使わずに完結する**のが標準。
- 参照資料（`references/`）・テンプレート・チェックスクリプトはすべて同梱で、スクリプトは標準ライブラリのみ・通信しない。
- 投稿規定・チェックリストは、ユーザーが手元のファイル（PDF・テキスト）として渡したものを読む。手元にない場合は同梱の既定値と `references/japanese-sources.md` の情報で書き、未解決リストに「投稿規定の確認」「チェックリスト最新版の確認」を入れる。
- 文献は、ユーザーが提示した文献（PDF・書誌情報・文献管理ソフトの書き出し）だけを使う。照合できない文献は載せず `【要文献】` にする。
- **Web検索・取得は、ユーザーが明示的に許可したときだけ**使う。許可があっても、送るのは公開情報の検索語（誌名・投稿規定・ガイドライン名・一般的な医学用語・公開文献の DOI/PMID）だけにし、原稿の文面・症例の固有情報・未発表の結果は含めない。
- ネットワークを使わなかったことで確認できなかった事項は、推測で埋めず未解決リストに残す。

## 0. 基本姿勢（全工程で守る）

- **データは著者が出したものだけを使う**。症例数・検査値・p値・信頼区間・年齢・期間など、ユーザーが提示していない数値は作らない。足りなければ本文に `【要確認：○○の数値】` と書き、末尾の未解決リストに入れる。
- **文献は実在を確認できたものだけ**を引用する。PubMed・医中誌Web・J-STAGE・DOI で確認できない文献は書かない（ICMJE 2025年改訂で、引用の正確性は著者責任と明記された）。確認できない場合は `【要文献：○○を支持する文献】` とする。
- **「ありそうな事実」も補わない**。数値だけでなく、手順の順序（例：「抗菌薬投与前に採取した血液培養」）、実施の有無（生検・心エコー等）、受診経路なども、提示がなければ事実として書かない。臨床的に当然そうだろうと思える箇所ほど要確認にする。補ってはいけないものの全体像：
  - 文献・DOI・PMID・URL・引用文
  - 結果の数値・分母・単位・効果量・信頼区間・検定名・有意性
  - 方法の詳細（使用機器・試薬・統計ソフトとその版・解析方針・プロトコル逸脱）
  - 倫理承認・同意・試験登録・日付
  - 著者・著者順・著者貢献・謝辞の対象
  - 研究資金・COI・データ共有の可否・生成AIの使用申告
  定型文（「開示すべき利益相反はない」等）も、著者が該当すると確認するまでは事実として置かない。
- **医学的判断・結論は著者のもの**。考察で「〜と考えられる」と書く主張は、結果か引用文献のどちらかに必ず紐づける。
- **個人情報を守る**。患者が特定されうる情報（氏名・イニシャル・ID・詳細な日付・住所・職業・施設名＋希少疾患の組合せ等）は書かない。症例報告では「X年Y月」形式に置き換える。名前を消しただけでは匿名化として不十分なことがある（稀少疾患・地域・年齢の組合せ）。病歴は個人情報保護法の要配慮個人情報であり、医療職には守秘義務がある。詳細は `references/privacy-law.md`。ユーザーから受け取った資料に個人情報が含まれていたら、原稿に転記せず、匿名化が必要な箇所として指摘する。
- **機密を外に出さない**。未発表原稿・査読コメント・患者情報・未公開データを、Web検索のクエリや外部サービスに入れない（上の「完全ローカル」を参照）。
- **他人の著作物を勝手に載せない**。他の論文・書籍・ガイドラインの図表を転載・改変する場合は出版社等の許諾が必要になることが多い（著作権法の「引用」の範囲は狭い）。許諾の有無を著者に確認し、未確認なら要確認にする。
- **ドラフト表示を外すのは著者**。原稿冒頭の `<!-- DRAFT -->` 等の下書き表示と「投稿可能」の判断は、著者が全項目を確認してから行う。スキル側から「投稿できる状態です」と断言しない。

## 0.5 科学的な書き方の原則

文章の表記より上位にある、内容の誠実さの原則。考察と抄録で崩れやすい。
- 不確実性を消さない。信頼区間・限界・別の解釈を残す。
- 検証的解析・探索的解析・事後解析（post hoc）を区別して書く。事後解析を主解析のように書かない。
- 観察研究の関連を因果として書かない（「〜により改善した」ではなく「〜と関連していた」）。
- 有意差なしを「差がない」「同等である」と書かない（同等性・非劣性は専用の設計と解析が必要）。
- 二値アウトカムは各群の事象数/分母を示し、絶対効果（リスク差：%ポイント）と相対効果（リスク比・オッズ比）を区別する。オッズ比をリスク比として言い換えない。ベースラインリスクなしに絶対効果を推定しない。
- 陰性・無効・有害事象・予想外の結果も、研究の記録に属するなら報告する。
- 結論は、そのデザイン・対象集団・不確実性で言える範囲にとどめる。

## 1. 受付：何を書くか確定する

最初に以下を把握する。ユーザーの依頼・添付資料から読み取れるものは聞かない。読み取れず、かつ結果が大きく変わるものだけを一度にまとめて聞く。

| 項目 | 例 | 影響 |
|---|---|---|
| 論文種別 | 原著／症例報告／短報／総説／系統的レビュー／学会抄録／研究計画書 | 構成・ガイドライン |
| 研究デザイン | RCT／コホート／症例対照／横断／診断精度／予測モデル／質的研究／QI | 報告ガイドライン |
| 投稿先 | 誌名・学会名 | 投稿規定（字数・句読点・文献書式） |
| 手持ち材料 | データ表・統計出力・症例経過・既存原稿・査読コメント | 書ける範囲 |

投稿先が分かれば、その誌の投稿規定（ユーザーが渡したファイル、またはユーザーが許可した場合は Web から取得）を読み、`assets/journal_policy_record.md` に確認日つきで記録する（規定は毎年変わるため記憶で書かない。誌による違いの例は `references/japanese-sources.md`）。生成AIの使用を論文種別ごとに禁止・制限している誌もあるので、書き始める前に確認する。取得できない場合は一般的な和文誌の慣行で書き、その旨を明記する。

## 2. 報告ガイドラインを選ぶ

`references/guidelines.md` を読み、デザインに合うガイドラインを選ぶ。チェックリストの各項目が原稿のどこで満たされるかを、最後に対応表として出す。

## 3. 材料を台帳にする（claims ledger）

本文を書く前に、使う事実を `assets/claims_ledger.csv` 形式で一覧化する。
- 列：`id, 主張, 種別(データ/文献/手続き), 出典, 出典の役割, 解析単位, 比較対象, 調整, 不確実性, 時点, 状態(確認済/要確認), 確認者, 確認日`
- 数値の主張は「解析単位（患者/病変/画像）・比較対象・調整の有無・不確実性（CI/SD/IQR）・時点」が揃っているかを見る。欠けた列があれば本文でも文脈が欠けている。
- `出典の役割`（一次研究／総説／ガイドライン／添付文書・規制文書／学会抄録）が主張に合っているか確認する。添付文書や保険収載を臨床効果の根拠にしない、総説を一次データの代わりにしない。
- 本文の数値・事実はすべてこの台帳のどれかに対応させる。対応がない文は書かないか、要確認にする。
- 文献の「確認済」は、**人が原典を開いて**主張を支持することと書誌情報を確かめた場合だけ。検索結果のスニペット、AIの要約、記憶、他論文の文献リストは手がかりにはなるが確認にはならない。確認した人と日付を `確認者`・`確認日` 列に残す。
- 文言を大きく直したら、対応する台帳の行も見直す（言い換えで主張が強くなることがある）。

台帳を作ると、書いている途中で数値を「それらしく」補ってしまう事故を防げる。短い学会抄録でも、頭の中ではなくファイルで作る。

## 4. 構成を決めてから本文を書く

`references/structure.md` で種別ごとの構成・字数の目安を確認し、`assets/templates/` の該当テンプレートをコピーして骨子（見出し＋各段落の要点1行）を作る。骨子で論理の流れを確認してから本文化する。

本文（方法→結果→考察→緒言）を先に固め、抄録と表題は最後に書く。本文は `references/style-ja.md` の表記規則に従う。要点：
- 文体は**である調**で統一（投稿規定が指定する場合はそれに従う）。
- 動詞の強さをデザインに合わせる（観察研究は「関連していた」、症例報告は一般化しない）。style-ja.md の「主張の強さ」表を参照。
- 箇条書きで本文を済ませない。結果と考察は段落の文章で書く。
- 数字・単位・統計表記は半角。数値と単位の間は半角スペース（SI 慣行、例：5 mg）。誌規定が異なればそれに従う。
- 略語は初出で「日本語正式名（英語正式名：略語）」と定義する。
- 薬剤は一般名。商品名が必要なら初出で一般名（商品名®、製造販売元）。

## 5. 倫理・申告事項を必ず書く

`references/ethics-coi.md` を読み、以下を本文（方法の末尾か専用欄）に入れる。抜けると査読前に差し戻される項目なので、材料がなければ要確認として残す。
- 倫理審査委員会の名称と承認番号、準拠指針（いわゆる症例報告は倫理指針上の「研究」に当たらないとされるが、投稿規定・施設規程の扱いを確認する。`references/japanese-sources.md`）
- インフォームド・コンセント（文書同意／オプトアウト）、症例報告の本人同意（写真を載せる場合は掲載範囲を含めて）
- 臨床試験登録（jRCT／UMIN-CTR 等）と登録番号
- 利益相反（COI）開示、研究資金
- 著者貢献（CRediT 等、誌が求める場合）とデータ共有声明
- 生成AIの使用申告（誌の規定に従う）

## 6. 文献を整える

`references/citations.md` の書式で文献リストを作る。誌指定の書式が最優先。各文献の書誌情報（著者・題名・誌名・年・巻・頁）は、ユーザーが提示した原典で照合する。ユーザーが許可した場合のみ、公開文献の DOI/PMID で Web 照合してよい。照合できないものは載せない。

## 7. 抄録（和文・英文）

- 和文抄録は構造化（目的・方法・結果・結論）が基本。字数は投稿規定で必ず確認。
- 英文抄録は和文本文の内容と一致させる。和文にない数値を英文で足さない。
- キーワードは MeSH／医中誌シソーラスの用語を優先。

## 8. 投稿前チェック（機械＋目視）

原稿を Markdown かテキストで保存し、スクリプトを実行する。

```bash
python3 scripts/lint_ja.py --draft manuscript.md   # 下書き段階：マーカー・仮置き（TBD/XX/○○）は件数のみ集計
python3 scripts/lint_ja.py manuscript.md           # 投稿前：マーカー残存も ERROR
python3 scripts/check_refs.py manuscript.md        # 引用番号と文献リスト、図表番号と参照の対応
python3 scripts/check_numbers.py manuscript.md     # 抄録の数値が本文・表にあるか＋割合の再計算
python3 scripts/check_privacy.py manuscript.md     # 年月日・ID・住所・敬称など個人情報の候補
```
すべてローカルで動き、通信しない。機密性の高い原稿では `lint_ja.py --no-echo`・`check_privacy.py --no-echo` を付けると、出力に原稿の文面を含めない。
- `check_privacy.py` の検出は候補にすぎず見逃しもある。図表・画像・表のセル・ファイルのメタデータは人が確認する。

- `check_numbers.py` は抄録と本文の数値の不一致（抄録だけ書き換えた・英文抄録だけに数値がある）を拾う。本文に同じ数があっても意味が同じとは限らないので、最後は台帳で確認する。
- `lint_ja.py` の ERROR は原則すべて直す。WARN は文脈で判断し、意図的に残すものは理由を把握しておく。
- 機械チェックは表記の一部しか見られない。最後に、台帳と本文の数値（本文・表・抄録の三者一致）、チェックリスト対応表、倫理申告の有無を目視で確認する。

## 8.5 投稿前セルフ査読

機械チェックの後、`references/self-review.md` に沿って査読者の立場で読み直す。統計の記述は `references/statistics-checklist.md` で点検する。指摘は「場所・観察・基準・重要性・対応」で書き、主要な主張を「維持／弱める／修正／削除」で判定する。最後に3段階の総合判定と、投稿を妨げる問題の上位3件を添える。lint の指摘0件を「投稿可能」の根拠にしない。

## 9. 納品物

毎回、次の形で返す。
1. 原稿本体（指定形式。指定がなければ Markdown、必要に応じて docx）
2. 報告ガイドライン対応表（項目番号 → 原稿の該当箇所）
3. **未解決リスト**：`【要確認】【要文献】` の一覧と、著者が埋めるべき情報
4. lint 結果の要約（残した WARN とその理由）
5. セルフ査読の結果（総合判定、上位の問題、主張の判定）

## 既定値で書くとき（投稿規定・チェックリストが手元にない）

作業は止めない。既定値（である調、「、。」、Vancouver系）で書き、チェックリスト対応表には「版・項目文言は未確認（同梱資料・記憶ベース）」と明記し、未解決リストに「投稿規定の確認」「チェックリスト版の確認」「全文献の書誌照合」を入れる。句読点・文献書式・誌名表記・表題の定型・AI 使用の可否は誌によって正反対になりうるので、投稿先が決まったら一括で直す前提で作る。

## 練習用・架空症例の場合

ユーザーが練習・教材・架空症例と言った場合は、冒頭に `<!-- 練習用の架空症例。投稿不可 -->` を入れる。同意・倫理承認・COI など**実在しない手続きを事実として書かない**（例文の「文書による同意を得た」をそのまま使わない）。該当欄は `【要確認：実症例では○○を記載】` とする。架空でも、ユーザーが示していない数値を補わない原則は同じ（練習の目的は書き方の型を学ぶことで、もっともらしいデータを作ることではない）。

## 推敲・査読対応の依頼の場合

- 既存原稿の推敲では、著者の主張・データ・結論を変えない。表記・論理の流れ・冗長さを直し、内容に関わる指摘は「提案」として別記する。
- 査読対応は次の順で進める。
  1. 各コメントを「表記・論理／科学的内容／統計／方針・規定／判断保留」に分類する。
  2. 事実やデータが変わる指摘は、**先に台帳を更新**してから本文を直す。
  3. 直したら lint・check_refs・check_numbers を再実行する。
  4. コメントごとに「コメント要旨 → 回答 → 原稿の変更箇所（頁・行）」の表で回答書を作る。複数の論点を含むコメントは分けて個別に答える。各回答には、変更箇所・図表・文献・「対応しない理由」のいずれかを必ず付ける（根拠のない「修正しました」を書かない）。
  - 実施していない解析・追加実験を、著者の確認なしに約束しない。「追加解析を行った」と書けるのは結果が台帳にある場合だけ。
  - 査読者の誤読と思われる指摘には、該当箇所を示して丁寧に説明し、誤読を招いた記述は直す。過剰な謝辞や賛辞を並べない。
  5. データの捏造・不都合な結果の削除・過大な主張につながる要求には従わず、その理由を回答に書く案を著者に示す。
  - 査読コメントは機密なので、外部サービスや検索クエリに貼らない。反論する場合も根拠（データか文献）を示し、丁寧語で書く。テンプレートは `assets/templates/reviewer-response.md`、lint は `--allow-desu` を付けて実行する（回答書はです・ます調のため）。
