# 日本語医学論文スキル

和文の医学論文を「投稿してそのまま査読に出せる」水準まで仕上げるための手順。
最優先は**事実の忠実性**。文章のうまさより、書いてある数値・引用・手続きがすべて本物であることのほうが重要。医学論文で捏造された数値や存在しない文献が一つでも混ざると、著者の研究者生命と患者の安全の両方を損なうため。

## 0. 基本姿勢（全工程で守る）

- **データは著者が出したものだけを使う**。症例数・検査値・p値・信頼区間・年齢・期間など、ユーザーが提示していない数値は作らない。足りなければ本文に `【要確認：○○の数値】` と書き、末尾の未解決リストに入れる。
- **文献は実在を確認できたものだけ**を引用する。PubMed・医中誌Web・J-STAGE・DOI で確認できない文献は書かない（ICMJE 2025年改訂で、引用の正確性は著者責任と明記された）。確認できない場合は `【要文献：○○を支持する文献】` とする。
- **「ありそうな事実」も補わない**。数値だけでなく、手順の順序（例：「抗菌薬投与前に採取した血液培養」）、実施の有無（生検・心エコー等）、受診経路なども、提示がなければ事実として書かない。臨床的に当然そうだろうと思える箇所ほど要確認にする。
- **医学的判断・結論は著者のもの**。考察で「〜と考えられる」と書く主張は、結果か引用文献のどちらかに必ず紐づける。
- 患者が特定されうる情報（氏名・イニシャル・ID・詳細な日付・施設名＋希少疾患の組合せ等）は書かない。症例報告では「X年Y月」形式に置き換える。

## 1. 受付：何を書くか確定する

最初に以下を把握する。ユーザーの依頼・添付資料から読み取れるものは聞かない。読み取れず、かつ結果が大きく変わるものだけを一度にまとめて聞く。

| 項目 | 例 | 影響 |
|---|---|---|
| 論文種別 | 原著／症例報告／短報／総説／系統的レビュー／学会抄録／研究計画書 | 構成・ガイドライン |
| 研究デザイン | RCT／コホート／症例対照／横断／診断精度／予測モデル／質的研究／QI | 報告ガイドライン |
| 投稿先 | 誌名・学会名 | 投稿規定（字数・句読点・文献書式） |
| 手持ち材料 | データ表・統計出力・症例経過・既存原稿・査読コメント | 書ける範囲 |

投稿先が分かれば、その誌の投稿規定を WebSearch/WebFetch で取得して読む（規定は毎年変わるため記憶で書かない）。取得できない場合は一般的な和文誌の慣行で書き、その旨を明記する。

## 2. 報告ガイドラインを選ぶ

`references/guidelines.md` を読み、デザインに合うガイドラインを選ぶ。チェックリストの各項目が原稿のどこで満たされるかを、最後に対応表として出す。

## 3. 材料を台帳にする（claims ledger）

本文を書く前に、使う事実を `assets/claims_ledger.csv` 形式で一覧化する。
- 列：`id, 主張, 種別(データ/文献/手続き), 出典, 状態(確認済/要確認)`
- 本文の数値・事実はすべてこの台帳のどれかに対応させる。対応がない文は書かないか、要確認にする。

台帳を作ると、書いている途中で数値を「それらしく」補ってしまう事故を防げる。短い学会抄録でも、頭の中ではなくファイルで作る。

## 4. 構成を決めてから本文を書く

`references/structure.md` で種別ごとの構成・字数の目安を確認し、`assets/templates/` の該当テンプレートをコピーして骨子（見出し＋各段落の要点1行）を作る。骨子で論理の流れを確認してから本文化する。

本文は `references/style-ja.md` の表記規則に従う。要点：
- 文体は**である調**で統一（投稿規定が指定する場合はそれに従う）。
- 箇条書きで本文を済ませない。結果と考察は段落の文章で書く。
- 数字・単位・統計表記は半角。数値と単位の間は半角スペース（SI 慣行、例：5 mg）。誌規定が異なればそれに従う。
- 略語は初出で「日本語正式名（英語正式名：略語）」と定義する。
- 薬剤は一般名。商品名が必要なら初出で一般名（商品名®、製造販売元）。

## 5. 倫理・申告事項を必ず書く

`references/ethics-coi.md` を読み、以下を本文（方法の末尾か専用欄）に入れる。抜けると査読前に差し戻される項目なので、材料がなければ要確認として残す。
- 倫理審査委員会の名称と承認番号、準拠指針
- インフォームド・コンセント（文書同意／オプトアウト）、症例報告の本人同意
- 臨床試験登録（jRCT／UMIN-CTR 等）と登録番号
- 利益相反（COI）開示、研究資金
- 生成AIの使用申告（誌の規定に従う）

## 6. 文献を整える

`references/citations.md` の書式で文献リストを作る。誌指定の書式が最優先。各文献はPubMed/医中誌/DOIで書誌情報（著者・題名・誌名・年・巻・頁）を照合してから載せる。

## 7. 抄録（和文・英文）

- 和文抄録は構造化（目的・方法・結果・結論）が基本。字数は投稿規定で必ず確認。
- 英文抄録は和文本文の内容と一致させる。和文にない数値を英文で足さない。
- キーワードは MeSH／医中誌シソーラスの用語を優先。

## 8. 投稿前チェック（機械＋目視）

原稿を Markdown かテキストで保存し、スクリプトを実行する。

```bash
python3 scripts/lint_ja.py --draft manuscript.md   # 下書き段階：マーカーは件数のみ集計
python3 scripts/lint_ja.py manuscript.md           # 投稿前：マーカー残存も ERROR
python3 scripts/check_refs.py manuscript.md        # 引用番号と文献リストの対応
```

- `lint_ja.py` の ERROR は原則すべて直す。WARN は文脈で判断し、意図的に残すものは理由を把握しておく。
- 機械チェックは表記の一部しか見られない。最後に、台帳と本文の数値（本文・表・抄録の三者一致）、チェックリスト対応表、倫理申告の有無を目視で確認する。

## 9. 納品物

毎回、次の形で返す。
1. 原稿本体（指定形式。指定がなければ Markdown、必要に応じて docx）
2. 報告ガイドライン対応表（項目番号 → 原稿の該当箇所）
3. **未解決リスト**：`【要確認】【要文献】` の一覧と、著者が埋めるべき情報
4. lint 結果の要約（残した WARN とその理由）

## Web検索が使えない場合

投稿規定・最新チェックリスト・文献照合ができないときも作業は止めない。既定値（である調、「、。」、Vancouver系）で書き、チェックリスト対応表には「版・項目文言はWeb未確認（記憶ベース）」と明記し、未解決リストに「投稿規定の確認」「チェックリスト版の確認」「全文献の書誌照合」を必ず入れる。文献は一つも載せず、すべて `【要文献】` にする。

## 練習用・架空症例の場合

ユーザーが練習・教材・架空症例と言った場合は、冒頭に `<!-- 練習用の架空症例。投稿不可 -->` を入れる。同意・倫理承認・COI など**実在しない手続きを事実として書かない**（例文の「文書による同意を得た」をそのまま使わない）。該当欄は `【要確認：実症例では○○を記載】` とする。架空でも、ユーザーが示していない数値を補わない原則は同じ（練習の目的は書き方の型を学ぶことで、もっともらしいデータを作ることではない）。

## 推敲・査読対応の依頼の場合

- 既存原稿の推敲では、著者の主張・データ・結論を変えない。表記・論理の流れ・冗長さを直し、内容に関わる指摘は「提案」として別記する。
- 査読対応は、コメントごとに「コメント要旨 → 回答 → 原稿の変更箇所（頁・行）」の表で作る。反論する場合も根拠（データか文献）を示し、丁寧語で書く。テンプレートは `assets/templates/reviewer-response.md`、lint は `--allow-desu` を付けて実行する（回答書はです・ます調のため）。
