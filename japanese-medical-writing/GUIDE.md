# 使い方ガイド（はじめての方へ）

このガイドは、AI を使うのが初めての方でも、このスキルを安全に使えるように書いています。上から順に読めば使い始められます。

- 「スキル」とは、AI に「和文の医学論文はこう書く」という手順書・資料・点検ツールを持たせるものです。AI がこれを読みながら手伝います。
- このスキルは**執筆の手伝い**です。研究の中身、医学的な判断、投稿してよいかどうかの判断は、すべて著者（あなた）が行います。

## 1. このスキルでできること・できないこと

### できること

| 作業 | 例 |
|---|---|
| 論文の下書き | 原著論文、症例報告、短報、総説、学会抄録 |
| 日本語の推敲 | である調への統一、句読点、略語、言い過ぎの表現の修正 |
| 構成の点検 | 報告ガイドライン（CONSORT・STROBE・CARE など）の項目がそろっているか |
| 申告事項の確認 | 倫理審査、同意、利益相反（COI）、臨床試験登録、生成AI使用の書き漏れ |
| 機械的な点検 | 表記の誤り、文献番号のずれ、抄録と本文の数値の食い違い、割合の計算ミス、個人情報の消し忘れ |
| 査読への回答 | 回答書の作成 |
| 投稿前のセルフ査読 | 査読者の目で弱点を洗い出す |

### できないこと（著者が行うこと）

- **データを作ること**：AI はあなたが渡した数値・経過だけを使います。足りない情報は作らず `【要確認】` と書きます。
- **文献を「見つけて保証する」こと**：AI が挙げた文献でも、あなたが原典を開いて確認するまでは使えません。
- **医学的な正しさの保証**：内容の正誤は著者が判断します。
- **投稿してよいかの判断**：点検で問題が出なくても、それは「投稿できる」という意味ではありません。

## 2. 始める前に必ず確認する3つのこと

### ① あなたの施設は AI の利用を認めていますか

病院・大学によっては、患者情報や未発表データを AI（特にクラウドの AI）に入力することを禁止・制限しています。**分からなければ、使う前に施設の個人情報保護の担当部署か倫理審査委員会に確認してください。**

### ② 使う AI は「クラウド」ですか「ローカル」ですか

| 種類 | 例 | 入力した内容はどこへ行くか |
|---|---|---|
| クラウドの AI | Claude、ChatGPT、Gemini など（Webサイトやアプリ、API） | AI の会社のサーバーに送られる |
| ローカルの AI | 自分のパソコンや施設内のサーバーで動かす AI（Ollama など） | 手元・施設内から出ない |

**クラウドの AI に貼り付けた内容は、その時点で外部に送られています。後から取り消せません。**

クラウドの AI を使う場合は、入力した内容が AI の学習に使われない設定・契約になっているかも確認してください（個人情報保護委員会が注意を呼びかけています）。施設が契約している法人向けサービスがあれば、それを使います。

### ③ 渡す資料から患者を特定できる情報を消しましたか

クラウドの AI を使う場合は、氏名・カルテ番号・生年月日・具体的な日付・住所などを必ず消してから渡します（[5. 匿名化](#5-患者情報を消す匿名化)）。消していない資料を渡すと、このスキルは作業を止めます。

## 3. 使い方を選ぶ（3つの方法）

| 方法 | 安全性 | 手軽さ | 向いている人 |
|---|---|---|---|
| **A. ローカルの AI で使う** | ◎ 原稿が手元から出ない | △ パソコンの性能と準備が必要 | 患者情報を含む原稿を扱う人 |
| **B. クラウドの AI で使う** | ○ 匿名化すれば可（施設の許可が前提） | ◎ すぐ使える | 匿名化した原稿、架空症例の練習、公表済み論文の推敲 |
| **C. AI を使わずに使う** | ◎ | ○ | 点検ツールと手引きだけ使いたい人 |

迷ったら、まず **C（AIなし）で点検ツールを試し**、次に **B で架空の症例**を使って練習するのがおすすめです。

## 4. 準備（インストール）

### 共通：Python があるか確認する

点検ツールは Python（無料のプログラム実行環境）で動きます。

1. ターミナルを開きます（Mac：「ターミナル」アプリ、Windows：「PowerShell」）。
2. 次を入力して Enter を押します。

```bash
python3 --version
```

Windows では `python --version` または `py --version` を試してください。`Python 3.9` 以上の数字が出れば準備できています。出ない場合は https://www.python.org/downloads/ からインストールします（Windows ではインストール時に「Add Python to PATH」にチェックを入れます）。

> このガイドのコマンドで `python3` と書いているところは、Windows では `python` または `py` に読み替えてください。

### 共通：スキルを入手する

GitHub のこのページ右上の緑色の「Code」ボタン →「Download ZIP」でダウンロードし、展開します。`git` を使える方は：

```bash
git clone https://github.com/kajisho5/japanese-medical-writing.skill.git
```

展開すると `japanese-medical-writing` というフォルダがあります。これがスキル本体です。

### A. ローカルの AI で使う

Mac・Windows それぞれの詳しい手順を **[LOCAL_LLM.md（ローカル LLM 導入手順）](LOCAL_LLM.md)** にまとめています。流れは次のとおりです。

1. Ollama（AI を自分のパソコンで動かすソフト）を入れる
2. 日本語に対応した AI のモデルをダウンロードする（クラウドで動くモデルは選ばない）
3. 長い文章を扱えるように設定する（コンテキスト長 64k 以上）
4. OpenCode（AI に作業させる画面）を入れて Ollama とつなぐ
5. このスキルのフォルダを所定の場所にコピーする

> ローカルの AI は、クラウドの AI より文章の質が落ちることがあります。その場合も、点検ツール（C）は同じように使えます。

### B. クラウドの AI で使う

| 使うもの | スキルの置き場所 |
|---|---|
| Claude Code | `~/.claude/skills/` |
| OpenAI Codex | `~/.agents/skills/` |
| OpenCode（クラウドのモデルを選んだ場合） | `~/.agents/skills/` など |
| claude.ai（Web/アプリ） | リリースページの `.skill` ファイルを claude.ai のスキル機能でアップロード（手順は公式ヘルプ https://support.claude.com を参照） |

各ツールのインストール方法は、それぞれの公式ドキュメントに従ってください。

- Claude Code：https://docs.claude.com/en/docs/claude-code/overview
- OpenAI Codex（スキルの置き場所）：https://learn.chatgpt.com/docs/build-skills
- OpenCode：https://opencode.ai/docs

**クラウドの AI では、必ず匿名化した資料だけを渡してください。**

### C. AI を使わずに使う

インストールは Python だけです。ターミナルで、ダウンロード・展開したフォルダ（`japanese-medical-writing` フォルダが入っている場所）に移動して実行します。

```bash
python3 japanese-medical-writing/scripts/check_all.py 原稿.md
```

原稿は Word（`.docx`）・Markdown（`.md`）・テキスト（`.txt`）のどれでも点検できます。Word はそのまま渡してください（上付きの引用番号、表、変更履歴の挿入部分を読み取ります。ヘッダ・脚注・コメント・作成者名の個人情報も確認します）。古い形式の `.doc` は、Word で「.docx」として保存し直してください。文字コードは UTF-8・Shift_JIS のどちらでも構いません。

手引きとして読む場合は `japanese-medical-writing/references/` のファイルを開いてください。

| ファイル | 内容 |
|---|---|
| `style-ja.md` | 和文の表記ルール、言い過ぎない書き方 |
| `structure.md` | 原著・症例報告・抄録の構成 |
| `guidelines.md` | 研究デザインごとの報告ガイドライン |
| `ethics-coi.md` | 倫理審査・同意・COI・試験登録・AI使用の書き方 |
| `privacy-law.md` | 個人情報保護・守秘義務・著作権 |
| `japanese-sources.md` | 国内の公式資料、和文誌ごとの規定の違い |
| `statistics-checklist.md` | 統計の書き方の点検表 |
| `self-review.md` | 投稿前のセルフ査読 |
| `figures-tables.md` | 図表の点検表 |
| `citations.md` | 文献の書き方と確認方法 |

## 5. 患者情報を消す（匿名化）

### 手順

1. **原稿や経過メモを自分のパソコンに保存**します（まだ AI には貼らない）。
2. 次の置き換え表に沿って書き換えます。

| 元の記載 | 書き換え例 |
|---|---|
| 氏名・イニシャル | 消す（「患者」「本症例」） |
| カルテ番号・患者ID | 消す |
| 生年月日・年齢 | 生年月日は消す。年齢は、特定のおそれがあれば「70歳代」などにまとめる（実年齢を求める誌もあるので投稿規定も確認） |
| 日付（2025年4月3日） | 「X年Y月」「第Z病日」「入院3日後」 |
| 住所・地域 | 消す（必要なら都道府県まで、など投稿規定に従う） |
| 施設名・診療科 | 「当院」 |
| 職業・勤務先 | 消す（診断に必要なら「事務職」程度に） |
| 家族の情報 | 診断に必要な範囲だけ |
| 写真・画像 | 顔・刺青・名前入りのリストバンドを写さない。画像の中の文字（氏名・ID・撮影日）を消す |

3. **点検ツールで消し忘れを確認**します（自分のパソコンで実行。インターネットにはつながりません）。

```bash
python3 japanese-medical-writing/scripts/check_privacy.py 原稿.md
```

「個人情報の候補 0 件」になるまで直します。ただし、このツールは**すべてを見つけられるわけではありません**。最後は自分の目で確認してください。

4. **組み合わせに注意**：名前を消しても「珍しい病気＋地域＋年齢」の組み合わせで本人が分かることがあります。

## 6. AI への頼み方

### 基本の形

次の4つを伝えると、AI が迷わずに作業できます。

1. **何を書くか**（症例報告、原著、学会抄録など）
2. **投稿先**（決まっていれば誌名。投稿規定のファイルがあれば一緒に渡す）
3. **材料**（匿名化した経過メモ、データの表、統計の結果）
4. **状況**（匿名化済みか、施設の許可があるか、練習か）

### 例文

**症例報告（はじめての方はまず架空症例で練習するのがおすすめ）**

```
架空の症例で、症例報告の練習原稿を作ってください。
70歳代男性、発熱と腰痛で入院、血液培養で黄色ブドウ球菌、MRIでL3/4化膿性脊椎炎、
セファゾリン6週間で改善。投稿先は未定です。
```

**実際の症例報告（匿名化済み）**

```
匿名化済みの症例です。施設の規程上、AIの利用は認められています。
症例報告を書いてください。投稿先は〇〇学会誌で、投稿規定を添付します。
（匿名化した経過メモを貼る）
```

**原著論文の推敲**

```
添付の原著論文の日本語を、投稿前に点検して直してください。
内容や結論は変えず、表記と言い過ぎの表現だけ直してください。
```

**学会抄録**

```
学会抄録を書いてください。字数は全角600字以内、【目的】【方法】【結果】【結語】の形式です。
結果の数値は次の表のとおりです。（表を貼る）
```

**査読への回答**

```
査読コメントへの回答書を作ってください。コメントと、改訂した原稿を添付します。
```

※ 他人から査読を頼まれた原稿（あなたが査読者の場合）は、AI に入れないでください（[禁止事項](#9-禁止事項絶対にしないこと)）。

### 言葉で頼めること一覧

コマンドを覚える必要はありません。AI に普段の言葉で頼めば、AI が点検ツールを動かして、結果を分かりやすく説明します。

| こう頼む | AI がすること |
|---|---|
| 「投稿前に点検して」「チェックして」 | 表記・文献番号・数値・個人情報をまとめて点検し、直すところを説明 |
| 「個人情報が残ってないか見て」 | 日付・ID・住所・名前などの消し忘れ候補を示す |
| 「抄録の字数を数えて」 | 節ごとの字数を数え、上限との差を示す |
| 「病名や用語が古くないか見て」 | 改称された病名・職名、診断基準による名称の違い、表記ゆれを出典つきで示す |
| 「前後で矛盾してないか見て」「内旋と外旋が途中で入れ替わってない？」 | 左右・運動の方向・検査の陽性/陰性・病理の組織型などが節ごとに食い違っていないかを、候補（`check_consistency.py`）と一覧表で示す。どちらが正しいかはカルテ・病理報告書で確認してください |
| 「抄録と本文の数字が合ってるか確かめて」 | 数値の食い違い・割合の計算ミスを示す |
| 「文献番号と図表番号がずれてないか見て」 | 欠番・引用漏れ・順番のずれを示す |
| 「句読点を，．に統一して」「全角の数字を半角にして」「単位の前にスペースを入れて」 | 表記だけを直した別ファイルを作る（元の原稿はそのまま） |
| 「言い過ぎの表現を直して」「です・ます調をである調に」 | 推敲して、変えた箇所を一覧で示す |
| 「〇〇学会誌に出したい。投稿規定に合わせて」 | 投稿規定（ファイルを渡す）を読み、字数・書式・申告欄を合わせる |
| 「査読者の目で弱点を教えて」 | セルフ査読をして、直すべき点を重要な順に示す |
| 「どのガイドラインに沿えばいい？」 | 研究デザインに合う報告ガイドラインを選び、対応表を作る |
| 「英文抄録も作って」「カバーレターを作って」「査読の返事を書いて」 | 和文の内容に沿って作る（数値や結論を足さない） |
| 「使い方を教えて」「ローカルで使うには？」 | このガイドやローカル LLM の手順に沿って案内 |

### 上手に使うコツ

- **一度に全部を頼まなくて大丈夫**です。「まず骨子だけ」「次に考察」のように分けると、確認しやすくなります。
- AI が質問してきたら、分かる範囲で答えてください。分からないことは「分からない」で構いません（その部分は `【要確認】` として残ります）。
- 直してほしいところは具体的に伝えます（例：「考察の2段落目が長いので短く」）。

## 7. AI から返ってくるものの読み方

AI は毎回、次のものを返します。

| 返ってくるもの | 内容 | あなたがすること |
|---|---|---|
| 原稿 | 本文 | 内容が事実どおりか確認する |
| `【要確認：…】` | AI が知らない情報の場所 | あなたが正しい情報で埋める |
| `【要文献：…】` | 文献の裏付けが必要な場所 | 自分で文献を探し、原典を読んで入れる |
| `【二次情報：…】` | 報道や解説記事など、元の公式資料（一次資料）で確かめられていない情報 | 法令・指針・原著論文などの一次資料で確かめ、合っていれば印を外す。確かめられなければその記述を削る |
| 未解決リスト | 上の2つの一覧 | 上から順に片付ける |
| 報告ガイドライン対応表 | 項目ごとに原稿のどこに書いたか | 「要確認」の項目を埋める |
| 点検結果 | 表記・数値・個人情報の点検 | ERROR を直す |
| セルフ査読 | 査読者の目で見た弱点 | 直すかどうか判断する |

### いちばん大事なこと

**`【要確認】`・`【要文献】`・`【二次情報】` を1つも残したまま、投稿してはいけません。** それっぽい文章で埋めたり、定型文で済ませたりしないでください。

## 8. 投稿前の点検

**AI を使っている場合**：「投稿前に点検して」と頼むだけで、AI が下の点検を実行して結果を説明します。

**AI を使わない場合**：

1. 原稿を Word（`.docx`）・Markdown（`.md`）・テキスト（`.txt`）のどれかで保存します。
2. 次を実行します。

```bash
python3 japanese-medical-writing/scripts/check_all.py 原稿.md
```

| 表示 | 意味 |
|---|---|
| `ERROR` | 直す必要がある |
| `WARN` | 確認が必要（意図どおりなら残してよい） |
| `INFO` | お知らせ |
| `CHECK` | 個人情報の候補、または前後の記載の食い違いの候補（必ず目で確認） |

`check_all.py` が中で順に動かしているツールです（1つずつ実行することもできます）。

| ツール | 見るもの |
|---|---|
| `lint_ja.py` | 表記・文体、`【要確認】` などの残り、言い過ぎの表現、略語の定義。`--count` で字数 |
| `check_refs.py` | 文献番号・図表番号の対応と順序 |
| `check_numbers.py` | 抄録の数字が本文にあるか、割合の計算 |
| `check_privacy.py` | 個人情報の候補 |
| `check_terms.py` | 古い病名・用語、表記ゆれ |
| `check_consistency.py` | 左右・内旋/外旋などの方向・検査の陽性/陰性・病理の組織型が、前後で食い違っていないか |
| `format_ja.py` | 句読点などの表記をまとめて直す（別ファイルに出力。点検ではないので `check_all.py` には入っていません） |

表記をまとめて直したいときは（AI なしの場合）：

```bash
python3 japanese-medical-writing/scripts/format_ja.py --punct comma --zenkaku --unit-space 原稿.md
```

`原稿.formatted.md` という別ファイルができます（元の原稿は変わりません）。`--punct ten` で「、。」に、`--punct comma` で「，．」に統一します。

まとめ欄がすべて「OK」になっても、**それは機械で見られる範囲に問題がないというだけ**です。次も自分で確認してください。

- [ ] 本文・表・抄録の数値が元データと一致している
- [ ] 文献はすべて原典を読んで確認した
- [ ] 図表・画像に個人情報が写っていない
- [ ] 投稿規定（字数・句読点・文献の書き方）に合っている
- [ ] 共著者全員が最終稿を確認した
- [ ] 生成 AI を使ったことを、投稿規定に従って申告した

## 9. 禁止事項（絶対にしないこと）

### 個人情報・機密

| してはいけないこと | 理由 |
|---|---|
| 実名・カルテ番号・生年月日・具体的な日付・住所の入った資料を、クラウドの AI に貼る | 外部に送られ、取り消せない。個人情報保護法や守秘義務に反するおそれ |
| 施設が禁止しているのに AI を使う | 施設の規程違反 |
| 他人から査読を頼まれた原稿を AI に入れる | 査読の守秘義務違反。禁止している雑誌・出版社がある |
| 同意の範囲を超えて患者の写真や情報を載せる | 同意違反・肖像の問題 |
| 共同研究の契約で外部提供が禁止されたデータを AI に入れる | 契約違反 |

### 研究の誠実さ

| してはいけないこと | 理由 |
|---|---|
| AI に数値・検査値・症例数・結果を作らせる | 捏造（研究不正） |
| AI が書いた数値や経過を、元データと照合せずに使う | AI は間違えることがある |
| AI が挙げた文献を、原典を読まずに載せる | 存在しない文献や、内容が違う文献のことがある |
| 不都合な結果を削る・書き換える | 改ざん（研究不正） |
| 他の論文の文章をそのまま使う | 盗用 |
| 同じ内容を複数の雑誌に同時に投稿する | 二重投稿（言語が違っても禁止）。翻訳論文などの二次出版は、両誌の許可など決められた条件を満たした場合だけ認められる |
| 他人の論文・本を許可なく翻訳して載せる | 翻訳権の侵害のおそれ |
| 他の論文の文章を言い換えて、出典を示さずに使う | 盗用。剽窃チェックをすり抜けるための言い換えも同じ |
| 実際に書いた人を隠して他人の名前で発表する、貢献していない人を著者に入れる | 不適切なオーサーシップ（ゴースト・ギフト） |
| 架空の症例を、本物の症例として発表・配布する | 捏造。製薬企業の資料などへの転用も同じ |
| 他の論文・本の図表を許諾なしに転載する | 著作権侵害のおそれ |

### 書き方・申告

| してはいけないこと | 理由 |
|---|---|
| `【要確認】` `【要文献】` を残したまま、または適当な文で埋めて投稿する | 事実でない記載になる |
| 実際には取っていない同意・倫理承認を「得た」と書く | 虚偽記載 |
| 「利益相反なし」などの定型文を、確認せずに入れる | 虚偽記載のおそれ |
| AI を著者に入れる | AI は著者の条件を満たさない（国際的な合意） |
| AI を使ったのに申告しない | 申告を求める雑誌が多く、国際的な指針（ICMJE）も透明性を求めている |
| 点検ツールやセルフ査読の結果だけで「投稿できる」と判断する | 機械で見られる範囲は一部だけ |

## 10. AI がしないこと（頼んでも断ります）

このスキルを使っている AI は、次のことを頼まれても行いません。

- 渡されていない数値・検査値・日付・経過を作る
- 確認できない文献を載せる、文献をそれらしく作る
- 実際にあったか分からない同意・倫理承認・試験登録・COI を「あった」と書く
- 患者を特定できる情報を原稿に書き写す
- クラウドで動いているときに、実名などが入った資料で作業を続ける（止めて、匿名化の方法を案内します）。添付ファイルや画像・スクリーンショットの中の文字も同じです
- 原稿の文面や症例の情報を、Web 検索や外部サービスに送る
- 不都合な結果を削る、結果より強い主張に書き換える
- 他の論文の文章を出典なしで言い換える（剽窃チェックのすり抜けを含む）、他人の論文を許可なく翻訳する
- 代筆（ゴーストライティング）や、貢献していない人を著者に加える手伝い
- 架空の症例を、本物として発表・配布・販促に使うための作成
- 実施していない解析や追加実験を、査読回答で約束する
- 「投稿できる状態です」と断言する

断られたときは、理由と代わりの方法が示されます。

## 11. よくある質問

**Q. 架空の症例と言ったのに、作業してくれません。**
A. 「架空の症例です」「練習用です」とはっきり書いてください。名前が架空っぽいだけでは、本物の可能性があるため止まります。

**Q. `【要確認】` がたくさん出て、原稿が穴だらけです。**
A. 正常です。AI が知らない情報を作らずに残しているからです。未解決リストを見ながら、分かる情報を伝えれば埋まっていきます。

**Q. AI に文献を探してもらえますか。**
A. 探す手がかりを出すことはできます（Web 検索を許可した場合）。ただし、載せる前に必ずあなたが原典を読んで確認してください。原稿の文面や症例の情報は検索に使いません。

**Q. 句読点が「、。」になっていますが、投稿先は「，．」です。**
A. 投稿規定を渡すか、「句読点は，．で」と伝えてください。雑誌によって規定が違うので、投稿先が決まったら一括で直します。

**Q. Word の原稿でも点検できますか。**
A. できます。`.docx` のまま点検ツールに渡してください。`.doc`（古い形式）は `.docx` で保存し直します。AI に Word のまま渡せるかは、使う AI によります。

**Q. 共著者の名前が入っていると止められますか。**
A. 止まりません。著者・共著者・所属・謝辞・引用文献の著者は、患者の個人情報ではありません。点検ツールも、見出しが「著者」「所属」「謝辞」「文献」の節では人名・施設名を拾いません。

**Q. 子どもや亡くなった方の症例は？**
A. 子どもは代諾者（保護者など）の同意が必要で、可能なら本人への説明（アセント）も行います。亡くなった方の情報も、生きている方と同じように匿名化し、守秘義務・倫理指針・遺族への配慮の対象になります。

**Q. 統計の解析も AI にやってもらえますか。**
A. 原則として、あなたが統計ソフトで出した結果を原稿に転記する手伝いをします。解析をはっきり頼んだ場合だけ、使ったコードと手順を示して行い、その結果を使うかはあなたが判断します。

**Q. 症例報告に倫理審査は必要ですか。**
A. 国の倫理指針のガイダンスでは、いわゆる症例報告は指針の「研究」に当たらないとされています。ただし、多くの雑誌が患者本人の同意とその記載を求め、施設によっては届出が必要です。投稿規定と施設の規程を確認してください（`references/japanese-sources.md`）。

**Q. 点検ツールで「CHECK」が出ましたが、個人情報ではありません。**
A. 候補を広めに拾うので、問題ないものも出ます。一つずつ見て、本当に問題ないなら残して構いません。

**Q. 点検ツールが動きません。**
A. `python3 --version` で Python 3.9 以上が入っているか確認してください。Windows では `python3` の代わりに `python` または `py` を使います。ファイル名に空白がある場合は `"原稿 最終.md"` のように引用符で囲みます。
