# 投稿前セルフ査読

原稿が一通り書けたら、査読者の立場で読み直す。目的は「落とされる理由」を先に見つけること。褒める場所を探す必要はない。

## 1. 指摘の書き方（1件ずつ）

各指摘を次の5要素で書く。場所と根拠のない指摘は著者が直せない。

| 要素 | 内容 |
|---|---|
| 場所 | 節・段落・表図番号・行 |
| 観察 | 原稿に何が書かれている／いないか |
| 基準 | 何に照らして問題か（報告ガイドライン項目、統計の原則、投稿規定、台帳との不一致） |
| 重要性 | 結論の信頼性にどう影響するか |
| 対応 | 著者に求める具体的な修正 |

指摘は次の4種類に分ける。「書いていない」ことを「間違い」と混同しないため。
- **未記載**：やったはずだが書かれていない（例：欠測の扱い）
- **設計上の問題**：研究デザインに起因し、文章では直らない（→限界に書く）
- **不整合**：原稿内・台帳との矛盾が確認できる（例：抄録と本文の症例数）
- **研究公正上の懸念**：捏造・改ざん・盗用・二重投稿の疑い（→著者に直接伝える）

## 2. 主張ごとの判定

考察・結語の主な主張について、台帳の根拠と照らして判定する。

| 判定 | 意味 |
|---|---|
| 維持 | 根拠に見合った強さ |
| 弱める | 根拠より強い（例：観察研究で因果表現） |
| 修正 | 内容が根拠と食い違う |
| 削除 | 根拠がない |

「弱める」「修正」には言い換え案を付ける。

## 3. よく落とされる理由（チェックリスト）

- [ ] 研究課題が不明確、または緒言のギャップと目的がつながっていない
- [ ] 方法が再現できない（対象の選び方、評価項目の定義、解析が曖昧）
- [ ] 統計の記述不足・誤り（`statistics-checklist.md`）
- [ ] 結果を超えた解釈・一般化（`style-ja.md` の「主張の強さ」）
- [ ] 選択バイアス・交絡など限界への言及不足、または定型文のみ
- [ ] 先行研究の把握不足、総説の孫引き
- [ ] 図表が不正確・本文と不一致・不要な重複（`figures-tables.md`）
- [ ] 報告ガイドラインの項目欠落
- [ ] 倫理承認・同意・登録・COI の記載欠落
- [ ] 投稿規定違反（字数・書式・文献書式）
- [ ] 新規性の根拠が「先行研究が見つからなかった」だけ（検索方法を示していない）

## 4. ダブルブラインド査読誌の場合

査読用原稿から次を除く：著者名・所属、謝辞、施設名を推測させる記載、「我々の以前の報告では」型の自己引用（第三者として書く）、ファイルのメタデータ（作成者名）。

## 5. 総合判定の出し方

- 判定：「軽微な修正で投稿可」「中程度の改訂が必要」「現状では投稿困難」の3段階
- 必ず添える：投稿を妨げる問題の上位3件、体裁上の問題の上位3件、不足している根拠（台帳の要確認・要文献）

自動チェック（lint 等）で指摘が0件だったことは、査読に耐えることの保証ではない。セルフ査読の結果に「投稿可能」と断言せず、判断は著者に委ねる。
